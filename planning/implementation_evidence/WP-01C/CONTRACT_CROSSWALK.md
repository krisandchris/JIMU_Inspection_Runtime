# WP-01C G1 冻结契约对照

本表接续 [C1 开工前契约盘点](../../active/WP-01C/CONTRACT_INVENTORY.md)，核对总计划 §5 的逻辑名称、§7 AST 与 R2–R2.1.1 追加项。对照对象为 [冻结产品清单](primary_freeze_a1aec5dc27cc/snapshot.json) 和 [347 项 Schema 索引](../../../schemas/generated/index.json)。基线为 `2552affeb69fbc2594fe70724f895b0db0967d47`，608 个产品文件的清单摘要为 `a1aec5dc27cc99fa86c1efcfdfc9c026951e865b3e47a5f2a16eeaef4049a4d2`。

`S(module.Symbol)` 指 `schemas/generated/module.Symbol.schema.json`，对应 `src/jimu_runtime/domain/` 下的 Python 模块。箭头后的字段、分支或嵌套类型以左侧文件为 Schema 宿主。仅列 Python 符号处为别名或有限工程入口。Schema 有独立文件只表示可独立校验形状，持久化角色以索引的 `role` 及父记录为准。表末给出证据代号对应的 fixture 和正负测试位置。

## C1-01 至 C1-05 的复核结论

| Finding | 冻结证据和边界 |
|---|---|
| C1-01 规则定义与语义 TypeChecker | 表中 RD/TY 的实际入口和带位置诊断覆盖了 C1 的类型缺口。Rule AST 与三种实际使用位置使用同一 wire。单位绑定证据由有限输入提供，未知关系报 incomplete。谓词真值、Required Evidence Guard 的执行和 Bundle 编译由后续 WP 实现。 |
| C1-02 有限 authority 视图与持久运行记录 | 支撑入口是 S(validation.runtime_authority.RuntimeAuthorityRecords) 与 `validation.runtime_authority.validate_runtime_authority`。其中 Execution/Release/manifest/eligibility → `validation.producer_authority_inputs.ExecutionDefinitionPin`，ObjectRecord → `validation.authority_inputs.ObjectDescriptor`，NodeRun/Attempt → 同模块 `NodeRunDescriptor／AttemptDescriptor`，QuestionSelectionRecord 与实际调用 → `QuestionSelectionDescriptor`，ObservationBatch 与其实际 Facts/模型调用 → `ObservationResultDescriptor`，映射型 ToolExecution 与实际引用 → `ToolStepResultDescriptor`。B 的旧视图 Schema 原样验证。RA 的实际记录正例、错误 scope/版本/伪证负例及 DC 的 Guard 证据验证这些关联；AP/ND 覆盖无 N06、空 eligibility 与父链投影。完整真实历史、来源真实性及服务执行仍待后续 WP。 |
| C1-03 名称与根边界 | PersistedContract、ArtifactIdentity、PrimaryFactOutput、StepDependency、ConditionalBranch、OutputBinding、FactProducer、FactResult、TypeDefinitionProjection、FactSchemaCatalogue 均在前两表定位。额外的独立 ArtifactIdentity、通用 OutputBinding 和持久 FactSchemaCatalogue 仍无单独消费者及已冻结标准，因此没有为这些逻辑名称另发 wire。当前相应行为分别由精确引用、声明式输出映射和有限 Registry 加 Bundle inventory 表达。 |
| C1-04 GeometryResourceDefinition | 冻结交付为有界二维多边形外环，3–256 个唯一顶点、隐式闭合，有限坐标范围 `±(2^53−1)`，拒绝全共线，坐标系、单位及来源为精确引用。GR 同时覆盖 Pydantic 关系和 Schema 结构。ADR-022 对真实 Region 几何归属和空间求值仍为开放决定，工程交接解释了几何资源数据与该外部选择的界限。 |
| C1-05 Schema 与验收闭环 | C5 的独立覆盖扫描、全部新增持久分支 fixture、旧 B 字节核对、离线 Draft 2020-12、双导出，以及静态工具和 pytest 结果，以冻结批原始日志为准。G0–G12 的其余验证入口见 [独立矩阵](independent/PREFREEZE_MATRIX.md)。历史 exporter 扩展路径 mypy 诊断属于既有记录；本轮通过的 mypy 门禁明确为 `src/jimu_runtime`。 |

R2.1 对照也可按 F 项复核。F01/R3 由 AP、DC、ND 覆盖三级 owner、祖先 UNKNOWN 与子级 not_evaluated，以及选定 evaluation/trace。F02 由 IV、EX 覆盖 Remote Primary、显式例外、fallback 与实际版本分支。F03 由 IV、ND、RA 覆盖 shared／additional／fallback 的记录与关联。F04 沿用 B0 的规范投影和 child-first digest 证据。F05 由 IV、ND、RA 覆盖 grounding／step origin 与 authority 隔离。
