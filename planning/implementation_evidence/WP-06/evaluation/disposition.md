# WP-06 Evaluation native review disposition

Scope is the WP-04 product copy with manifest SHA-256 `924eb788eab11bed400ec1f3602a9a30d3df7b43cba79e8601901eb7921f7495`. The following resolutions are in the Evaluation package and its dedicated synthetic tests.

| Native finding | Disposition and regression |
|---|---|
| P1, empty review can remove adjudicated truth | Accepted. Truth publication requires recorded votes, and a change to a labeled entry requires an explicit adjudication. The regression proves rejection of an open or empty review and preservation of the original when an independent adjudicator explicitly abstains. |
| P1, votes and decisions can be reused across samples | Accepted. ReviewSubject binds dataset, scope, sample, catalogue, history and base truth. Adjudication pins the preceding history and exact selected vote digest. Tests reject cross-sample, stale revision and replaced vote content. |
| P1, negative Profile labels expand with the protocol | Accepted. Truth and review freeze the canonical EvaluationCatalogue independently of the IoU cutoff. A catalogue expansion is rejected. Re-scoring with only an IoU cutoff change remains supported. |
| P1, unsupported positive task Decision | Accepted. The scorer checks full DecisionRecord ownership against the predicted Execution/Release/Bundle/context/Profile/Object and checks exact Rule evaluations. A matched persisted Decision is required for a positive task, and every projected evaluated Rule needs its actual Object Decision. |
| P1, Execution input digest copied without verification | Accepted. SampleSource supplies independent accepted Task, Execution and execution input digests. Score reconciles these against the trusted TrialSource pin. A negative test changes the input while preserving source audit rows. |
| P1, observed bindings are global instead of per Profile | Accepted. The catalogue fixes Question–Fact Schema, geometry and Rule/category bindings per Profile. Both label and prediction must use the owning Profile's approved binding. The regression tries using a Question present solely on another Profile. |
| P1, Tool denominator can be altered by omitted attempts | Accepted. The independently pinned TrialSource journal inventory is required and reconciled for exact digest-set equality. Removing an attempt is rejected. |
| P2, extra ModelInvocation inflates statistics | Accepted. The trusted full journal is reconciled by exact digest-set equality. Execution-linked IDs continue to be mandatory, and other actual attempts can be supplied only through the full journal. Additional unlisted attempts are rejected. |
| P2, binary hit masks wrong category | Accepted. Separate category metrics use explicit complete label sets and the exact category mapped from each matched Rule. Unknown category assignments are tallied outside category denominators. The regression scores a binary TP alongside a per-category FP and FN. |
| P2, confirmed miss bound looks like full negative truth | Accepted. Renamed the all-NO_HITS statistic as a confirmed-miss lower bound. The labeled rate is undefined at zero target labels and the unknown sample count remains available. |
| P2, unmatched predictions disappear | Accepted. The report preserves every unmatched predicted Object and distinguishes confirmed false positives using complete grounding or confirmed Profile absence from unmatched predictions with incomplete truth. |
| P2, same wrong Value can count as correct | Accepted. Both sides undergo exact FactSchemaDefinition checks, including canonical identity and derived child, and strict typed value validation. Enum-valued geometry labels and predictions outside the allowed vocabulary are rejected independently. |
| P2, attribution evidence can cross sample boundaries | Accepted. EvidenceRef and digest must match the exact sample inventory in the pinned report. Cross-sample evidence is rejected. Independent human attachments require a separate future source contract. |
| P2, versions may roll back | Accepted. The previous implementation already requires strictly increasing semantic versions in ReviewHistory, TruthSnapshot, and BadCaseAttribution. The version-regression test remains in the suite. |
| P2, report details and summary can disagree | Accepted. Report decoding rechecks pins, identity, sample/Task/Execution/image uniqueness, per-sample object identities and the full recomputed summary. Tests reject duplicated samples, inflated summary and a replaced source pin. |

The pure scorer depends on the authenticated host for an independent full runtime journal export, approved pins, authoritative Profile bindings from the admitted Bundle, and durable historical retention. Runtime export or replay wiring and real-data evaluation are separate batches.
