# W4.4 单机资源准入与隔离工作者

## 范围和接口

主控在 WP-03 完成冻结验收后放行 W4.4。本批提供共享宿主额度账本、租约生命周期和经宿主登记的隔离进程执行。PostgreSQL 仍掌握 Task、Execution、Attempt、调用审计和权威输出。资源层由 W4.5 在派发边界接入。

- `src/jimu_runtime/workers/resource_inventory.py` 定义宿主库存配置，包括 CPU 槽位、远程额度桶、物理 GPU 与工作者池，以及部署或工具的精确 scope。GPU 的常驻与单次运行各有槽位，同时从一个物理设备显存预算扣减。不同工作者池归到同一个物理设备时共享该预算。
- `src/jimu_runtime/workers/resources.py` 提供 `ResourceAdmission` 和稳定的 `ResourceLease.lease_id`。SQLite `BEGIN IMMEDIATE` 在独立进程间原子计算和记账。调用审计使用 `lease_id`、`owner_id` 和 `scope_id`。续租、释放和取消核对完整 scope、租约和所有者代际。宿主 Telemetry 可查询状态，只有有效的预留可进入启动闸门。
- `src/jimu_runtime/workers/lifecycle.py` 和 `process_guardian.py` 负责受信命令、本机启动见证、有界 stdin/stdout、超时与取消。guardian 等待 SQLite 持久记录进程组与自身启动代际后才允许实际启动。调用方关闭控制通道或崩溃时，guardian 作为 Linux subreaper 结束工作并回收子孙进程。确认整棵进程树回收后，由 guardian 独立提交持久回执。有界回收超时后保留 draining，直到可信回执和 guardian 退出得到确认。
- `src/jimu_runtime/workers/process_identity.py` 记录 Linux boot ID、PID namespace 及传输进程的启动代际。重启 supervisor 可以在同一 PID namespace 读取持久回执并核对旧 guardian 是否已退出。仅原进程组消失且缺回执时保留占用，宿主 boot ID 变化后可自动清理。共享账本和 guardian 都应位于受信的单主机监督边界。

## 远端与恢复

远程额度桶需明确选择本机 HTTP 传输并发或供应方实际在途执行。前者由本机调用完成或其所有进程退出结算，速率限制由 HTTP/路由层执行。后者从 `activate_remote` 的派发边界计费，取消、网络超时、套接字关闭和 supervisor 重启后保留占用。用 `settle_provider` 按 lease 与 dispatch 身份交给宿主注入的终态证明验证器。缺证明时维持 draining。进程退出证明不能替代供应方终态证明。

每个物理宿主为这一版本配置唯一 inventory ID 和一份受信本地磁盘 SQLite 账本。所有资源持有者需连接该账本。启动服务只读物理身份与配置指纹并打开现有文件，缺失或不匹配时拒绝准入。`provision` 是明确的一次性宿主动作。更换配置或账本前先确认现有负载已经退出，保留旧账本用于排查和恢复。进程组守护依赖支持 pidfd 的 Linux 及同 namespace 的 procfs。只登记可信命令。使用 setsid 新建会话的后代仍须等待 guardian 回收；guardian 本身异常退出且缺回执时，宿主 reboot 是自动回收条件。僵尸 guardian 由父进程或宿主 init 回收。部署后跨 PID namespace 回收和真实 GPU 进程仍需独立验收。

SQLite 内部账本 v4 含库存指纹、绑定租约和 guardian 代际的回执、远程派发的 ARMED 状态和 provider dispatch 历史唯一记录。v1–v3 账本会明确拒开。运维切换须先完成在途执行、保留旧账本，并保证新库存分配全局唯一派发 ID 且终态验证器隔离旧证据。本批无 Domain wire 或 PostgreSQL 迁移。回退时先停止新派发并完成已在途工作，保留资源账本与历史执行审计，再撤销 W4.4 接线与实现。

## Guardian 异常退出复核

代码复核发现，guardian 被 SIGKILL 后，使用 setsid 建立独立会话的后代仍可存活，原进程组退出因此缺少全树终止证据。SQLite v2 的回执仅由被登记的 guardian 在确认没有子进程后提交，账本核对 lease ID、owner generation、guardian PID 和启动代际。账本仅在收到回执并核验 guardian 退出，或看到可信宿主 boot ID 变化后回收本机工作额度。回执提交失败时保持 draining。宿主重启前的人工恢复需要另行实现可核验的全域终止证明。

新增真实子进程回归覆盖两条故障路径。连接 supervisor 被强杀、guardian 仍存活时，普通进程组和 setsid 进程树均由 guardian 回收并持久落账，重开后可正常取下一代租约。guardian 本身被强杀、原组退出而 setsid 子进程仍活跃时，重开仍拒绝下一次准入。最后模拟 boot ID 变化验证回收，并校验旧持有者不能释放新租约。测试实际终止了隔离进程，宿主 reboot 仅用 fixture 模拟。异常回归首轮因 fixture 在 Linux subreaper 收养前调用 waitpid 而失败。等待 guardian 完成退出后，完整局部套件通过。

## 远端发送授权与封存工件

先由 `prepare_remote_send` 绑定 dispatch 并将租约置于 ARMED。此时占用额度，发送权尚未授予。取消和超时可以通过 `abort_remote_before_send` 释放当前 owner generation 对应的 ARMED dispatch，旧持有者、不同 dispatch、已获发送权或证据不完整的调用均无法撤销。最终 `activate_remote` 比较精确 lease 和 dispatch，并在 SQLite 事务中检查可选 monotonic deadline。授权与撤销争用同一事务边界，只能一方成功。provider 派发 ID 在撤销后仍不得复用。授权提交后仍无法确认是否实际发送时保留 PROVIDER_INFLIGHT，直到可信终态证明。本次不以 socket 状态推断远端执行。

本地执行器支持受信宿主显式传入一个封存的 memfd。进入异步队列前校验 WRITE、GROW、SHRINK、SEAL 并复制描述符，改写 argv 中的精确工件 `/proc/self/fd/<fd>` 参数。guardian 仅把该描述符传给实际 worker。调用方提前关闭原描述符时，复制件仍由执行线程或未出队的清理路径负责。
