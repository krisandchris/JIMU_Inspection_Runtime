# WP-04 独立验收矩阵

基线为 detached HEAD `2552affeb69fbc2594fe70724f895b0db0967d47`。WP-03 的 735 个冻结产品文件提供增量基准。初读状态有 16 个 tracked 修改和 324 个 untracked 状态项，包含上游契约、Schema、工作流和正在实现的 WP-04 adapter。正式验收只读冻结产品，本目录保存预检、探针和正式命令原始结果。

| 条件 | 独立证据 |
|---|---|
| 调度和物理派发 | 隔离 PostgreSQL 中按 operation 对照多个独立的物理发送、headers/响应边界和完整摘要。用原 Attempt 和 fence 写迟到结果，异 Attempt 复用原 ID 必须被拒。检查一次重试及未派发终态。 |
| 可信模型版本与撤销 | 通过实际入口重新读取当前登记。派发前撤销应留未派发回执。在途撤销核对网络只发送一次并保留完整回包摘要，适配器无可用于权威输出的内容。 |
| HTTP 与局部结果 | 自建 loopback 服务检查接收次数、序列化结构、已知响应摘要和独立请求 ID。至少覆盖成功、限流、响应读取上限、慢响应或主动取消。 |
| 显式模型 fallback | 两个独立回环端点按固定部署提供同一模型标识。主 POST 超时后由另一 owner 落第二 Attempt，复核触发错误、精确评审引用、固定 operation 和两份真实回执。 |
| Tool 部分失败和兄弟步骤 | A 成功且 B 首次失败。分别注入即时临时错误与实际超时。PG 保留父失败和独立子 Attempt，重试只发送 B，最终逐步结果保留真实 A 来源，验证全体 peers、独立派发及最后 N06 权威发布。 |
| 嵌套 Tool 调用 | 在独立编译的 vision_auxiliary Tool 运行中用两真实回环端点验证父尝试重试、原子 Attempt 和派发，随后变造回包中 Invocation ID 测试持久审计与权威拒绝。 |
| 容量和子进程生命期 | 同一 SQLite 资源账本由独立进程竞争。杀掉一个执行监督进程并核对工作子进程及脱离进程组的后代退出，新的监督进程才有容量。守护进程暂停、异常退出或线程排队逾期时，核对实际工作进程、回收证明和可用额度。旧 token 不得释放新租约。 |
| 契约与源边界 | 固定 WP-03 基线进行 347 个公开 Domain Schema 逐字节比较，独立生成两次，检查生成器、Ruff、strict mypy、全量 pytest JUnit 和锁。冻结前后使用同一产品清单。 |
| 外部容量与质量 | `RUNTIME_NOT_RUN`。本地验证不使用真实 Provider、GPU、权重、外部数据或生产数据库。 |

所有本地数据与网络监听均在独立临时资源中。SQL 只读核对和公开持久化接口分开，使用上一包已验证的容器夹具和 Release 配置骨架，再提供本包独立的 wire、资源工况和断言。未完成探针在预检日记保留实际结果。

验收 runner 支持全组运行，也可对同一冻结摘要分别运行 `runtime`、`static`、`pytest` 三组。每组独立建锁定 Python 运行环境并执行清单前后比对。
