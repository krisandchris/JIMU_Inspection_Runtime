# WP-07 本地运维、恢复与外部接口

本地验收以隔离部署、数据恢复后可复查、按调用人授权和受控健康检查为准。输入为 WP-05 已验证的本地 Worker、WP-06 版本化回放服务以及已验收的受理、准入和资源记录。开发子任务使用 gpt-6.2-sol / medium。原生 planner 已核查现有代码与运行环境。

| 交付与写入职责 | 工程契约 | 可验证结果与前置 |
|---|---|---|
| 备份与恢复演练 | 使用同一静止点的 PostgreSQL、Bundle/Release SQLite、ResourceAdmission SQLite、私有媒体文件树及 `.database`。清单记录各文件摘要、版本、逻辑数据库 UUID 和宿主受信配置身份。密钥通过独立受控位置恢复。 | 本地 Compose 项目或测试容器创建独立卷、实例及角色。从已验收镜像的 pg_dump/pg_restore 恢复到空目标。核验 Task、Release、Decision、证据及 lease，破损或不相符的包应被拒绝。WP-06 入库后扩充相同演练以覆盖回放、正式复核和保留记录。 |
| CPU Compose 与健康检查 | 使用镜像摘要、私有持久卷、最小权限角色和一致的非 root 文件所有者。服务入口装配 Intake、受理方的权限端口和 inspection_worker。健康检查分别覆盖进程、数据库和 Worker 取件能力。 | 启停、重建、恢复测试面向指定临时项目。对外端口只绑定回环，受理后用实际 trace 确认推进；模拟配置下的 GPU/Provider 质量留给对应环境验收。 |
| 外部 API 合同与授权 | 对规格 04 §10 每条候选路由逐一关联服务、Pydantic 输入输出、受信 actor、action 和项目/客户端范围。结果和 trace 的资源归属需从持久记录核验，trace 根据 event_number 分页并限制响应大小。证据区分原件、规范化及其他审计权限。Release 激活的范围与项目/客户端分别验证。 | 可独立编制 API 合同与本地角色测试。已评审的路由根据真实服务逐项验证。取消只引用原受理回执对应的 Execution，回放向新 Execution 投影。未定义的 accept/deprecate 操作保留现有状态机语义，适用契约确定后接入。 |
| 指标、trace 与仪表盘 | 关联 Task → Execution → NodeRun → Attempt → Invocation/ToolExecution。有限枚举用于指标维度，资源 ID 只进入受控 trace。队列、端到端、节点、模型、工具耗时只统计有对应时间的记录。来源不可观测的 token/GPU 值保留缺失态。 | 合成成功、超时、重试、取消和缺件各有可追溯观测。核验重启后累计统计、受限访问和日志脱敏。性能数字与使用的机器、样本、时间和运行版本一起报告。 |
| 需求平台适配设计 | 只定义显式版本合同、制品来源、外部身份到 Runtime 的映射和校验回执。 | 合成映射样例和兼容性检查独立评审。 |

## 恢复顺序和证据

1. 在获准的隔离目录与数据库建立有结果、进行中和待对账三类数据。记录身份、摘要、派发数。封存时停止新受理、调度和写入，确认已退出的写入方或已取得的一致快照。
2. 在不同临时卷还原。确认数据库 COMMENT、MigrationTarget、媒体根身份与备份对应，应用角色保持受限，私有文件树保持所有权和权限。外发端口关闭。
3. 验证快照中的原有 Release、执行、Decision 和物理证据。未确认的派发维持对账状态；随后在可观测回环环境恢复工作，核验独立调用数和新的 lease fence。
4. 记录实际工具版本、所有输入/输出摘要和退出码。正式主机、生产恢复、真实身份配置、真实模型和数据的验收按用户的后补授权执行。回退使用原封存输入和新的临时目标。

接口面原文及候选路由见 [技术架构](../../../specs/04_Runtime_Technical_Architecture_V1.0.md)。WP-06 写入方与 WP-07 运维演练各自使用隔离目录。最终验收只使用同一封存包上的组合结果。
